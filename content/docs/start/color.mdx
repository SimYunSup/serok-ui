Serok UI 디자인 시스템의 색상 팔레트에 대한 OKLCH 색상 공간 기반 분석 및 APCA 대비 검증 결과입니다.

## Adobe Spectrum 색상 시스템 원칙

Serok UI의 색상 시스템은 [Adobe Spectrum의 색상 재설계](https://adobe.design/stories/design-for-scale/reinventing-adobe-spectrum-s-colors) 원칙을 참고하여 설계되었습니다.

### 14단계 색상 스케일 (100-1400)

각 색상 패밀리는 14개의 명도 단계를 제공합니다:

| 범위 | 배경 기준 | 용도 | 테마 |
|------|-----------|------|------|
| **100-500** | 검은색 (#000) | 밝은 색상 - 다크 모드 텍스트/아이콘 | Dark/Darkest |
| **600-1000** | 흰색 (#FFF) | 어두운 색상 - 라이트 모드 버튼/텍스트 | Light |
| **1100-1400** | 흰색 (#FFF) | 고대비 색상 - WCAG AAA 접근성 | High Contrast |

### Stevens' Power Law 적용

Adobe Spectrum은 선형 분포 대신 **Stevens' Power Law**를 적용한 다항식 곡선을 사용합니다. 이를 통해 컴포넌트 상태 변화(hover, active, focus)에서 더 자연스럽고 균형 잡힌 명도 분포를 제공합니다.

### Simultaneous Brightness Contrast

동일한 WCAG 대비율이라도 라이트/다크 모드에서 인지되는 밝기가 다릅니다:

- **라이트 모드**: 텍스트와 아이콘이 점진적으로 어두워짐 (gray-700 → gray-900)
- **다크 모드**: 텍스트와 아이콘이 점진적으로 밝아짐 (gray-300 → gray-100)

## OKLCH 색상 공간으로의 전환

Serok UI의 모든 색상은 이제 **OKLCH 색상 공간**을 사용합니다. OKLCH는 RGB나 HSL 대비 다음과 같은 장점을 제공합니다:

- 지각적으로 균일한 명도 (Perceptually uniform lightness)
- 더 나은 색상 보간 및 그라데이션
- 더 정확한 색상 대비 계산
- 현대 디스플레이를 위한 넓은 색영역 지원

## APCA 대비 분석

Adobe Spectrum 원칙에 따라, 색상 단계별로 적절한 배경색을 기준으로 대비를 측정합니다:

- **100-500 (밝은 색상)**: 검은색 배경 기준 - 다크 모드에서 텍스트/아이콘으로 사용
- **600-1000 (어두운 색상)**: 흰색 배경 기준 - 라이트 모드에서 버튼/텍스트로 사용
- **1100-1400 (고대비 색상)**: 흰색 배경 기준 - 고대비 접근성 모드

### APCA 임계값 기준

- **본문 텍스트**: ≥ 75 Lc (일반 크기 텍스트)
- **큰 텍스트**: ≥ 60 Lc (제목, 큰 UI 텍스트)
- **UI 컴포넌트**: ≥ 45 Lc (아이콘, 테두리 등)

## 색상 사용 가이드

Adobe Spectrum 원칙에 따른 색상 단계별 권장 사용법입니다.

### 버튼 및 액션

| 상태 | 색상 단계 | 예시 |
|------|-----------|------|
| 기본 | 700 | `--serok-purple-700` |
| Hover | 800 | `--serok-purple-800` |
| Active | 900 | `--serok-purple-900` |
| Disabled | 500 (opacity 50%) | `--serok-gray-500` |

### 텍스트 (라이트 모드)

| 중요도 | 색상 단계 | 설명 |
|--------|-----------|------|
| 기본 텍스트 | 900 | 본문 및 주요 콘텐츠 |
| 보조 텍스트 | 700 | 부가 정보 |
| 비활성 텍스트 | 500-600 | 힌트, 플레이스홀더 |

### 텍스트 (다크 모드)

| 중요도 | 색상 단계 | 설명 |
|--------|-----------|------|
| 기본 텍스트 | 100-200 | 본문 및 주요 콘텐츠 |
| 보조 텍스트 | 300 | 부가 정보 |
| 비활성 텍스트 | 400-500 | 힌트, 플레이스홀더 |

### 배경 및 표면

| 용도 | 색상 단계 | 예시 |
|------|-----------|------|
| 페이지 배경 | 0-50 | `--serok-gray-0` |
| 카드 표면 | 50-100 | `--serok-gray-50` |
| 강조 배경 | 100-200 | `--serok-purple-100` |

## OKLCH 색상 공간 이해하기

**OKLCH**는 지각적으로 균일한 색상 공간으로, 세 가지 구성 요소로 색상을 표현합니다:

- **L (Lightness, 명도)**: 0-100%, 색상의 지각적 밝기를 나타냅니다
- **C (Chroma, 채도)**: 0-0.4+, 색상의 선명도 또는 포화도를 나타냅니다
- **H (Hue, 색상)**: 0-360°, 색상환에서의 각도 (빨강, 노랑, 초록, 파랑 등)

## APCA 대비 알고리즘 이해하기

**APCA (Accessible Perceptual Contrast Algorithm)**는 WCAG 2.x의 전통적인 대비율보다 더 정확한 가독성 예측을 제공하는 현대적인 대비 계산 방법입니다.

### APCA 대비 레벨 (Lc 값)

- **본문 텍스트 (≥75 Lc)**: 일반 크기의 텍스트 콘텐츠에 필요
- **큰 텍스트 (≥60 Lc)**: 제목 및 큰 UI 텍스트에 적합
- **UI 컴포넌트 (≥45 Lc)**: 아이콘, 테두리 등 비텍스트 요소의 최소 기준

APCA에 대한 자세한 내용은 [git.apcacontrast.com](https://git.apcacontrast.com/)에서 확인하실 수 있습니다.

## 분석 및 고찰

이 색상 분석 시스템과 현재 접근 방식은 Serok UI 철학을 부분적으로 반영하지만, 개선의 여지도 있습니다.

### 성과 및 장점

- **검증된 기술 활용**: Adobe Leonardo와 culori 같은 입증된 라이브러리를 사용하여 빠르게 OKLCH 전환 및 APCA 검증 구현
- **자동화된 분석**: StyleDictionary 변환 파이프라인을 통해 hex → OKLCH 변환이 자동으로 이루어지며, 수동 작업 불필요
- **시각적 인사이트**: 통합 그래프를 통해 모든 색상 패밀리의 명도/채도/색상 분포를 한눈에 파악 가능
- **접근성 우선**: APCA 대비 분석으로 WCAG 3.0 기준 준수 여부를 체계적으로 검증

### 색상 팔레트의 한계

- **불균일한 명도 분포**: 위 그래프에서 확인할 수 있듯이, gray와 yellow 계열의 lightness가 일정한 기울기로 증가하지 않고 중간 구간에서 급격한 변화를 보임. 이상적으로는 모든 색상 단계가 지각적으로 균일한 간격을 가져야 하지만, 현재는 시각적으로 불균형한 느낌을 줄 수 있음
- **APCA 기준 미충족 색상 존재**: 색상 팔레트 생성 시 APCA 대비를 사전에 고려하지 않아, 일부 색상 조합이 접근성 기준을 만족하지 못함. 특히 밝은 색상들은 흰색 배경에서, 어두운 색상들은 검은색 배경에서 충분한 대비를 확보하지 못하는 경우가 많음
- **체계적 생성 방법론 부재**: 현재 색상 팔레트는 수동으로 선택된 hex 값을 기반으로 하며, Adobe Leonardo의 색상 생성 기능을 활용하지 않음. 대신 기존 hex 값을 OKLCH로 변환만 하여, 색상 간의 관계나 대비가 체계적으로 설계되지 않았음

### Serok UI 철학과의 정합성

#### 철학 준수 측면

- **"검증된 기반 위에 구축"**: Adobe Leonardo와 culori 같은 업계 표준 라이브러리 활용
- **"제한된 리소스 존중"**: 복잡한 색상 이론을 직접 구현하지 않고, 기존 도구를 조합하여 효율적으로 구현

#### 철학 미준수 측면

- **"검증된 기반 활용의 불완전성"**: Leonardo의 색상 생성 기능을 활용하지 않고, 단순히 검증 도구로만 사용. 라이브러리의 핵심 가치를 충분히 활용하지 못함

> **현재 색상 팔레트의 문제점을 명확히 드러냄**으로써 가치를 제공합니다. 색상 선택이 다른 방식으로 이루어져 완벽한 색상 시스템을 구축하지는 못했지만, 무엇이 부족한지 정직하게 보여주는 것을 보여주기 위해 이 분석을 작성했습니다.
