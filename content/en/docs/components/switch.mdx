# Switch

## Overview

A switch is a form control that allows users to toggle a binary option on or off. Switches are commonly used in settings, preferences, and feature toggles. Serok UI's Switch component extends React Spectrum's Switch with custom variants and styling.

## Quick Start

Minimal working example showing the most common usage pattern:

```tsx
import { Switch } from '@/components/ui/Switch';

export function MyComponent() {
  return <Switch>Enable notifications</Switch>;
}
```

## Props

| Prop | Type | Required | Default | Description |
|------|------|----------|---------|-------------|
| `isSelected` | `boolean` | No | — | Controlled selected state |
| `defaultSelected` | `boolean` | No | `false` | Uncontrolled initial selected state |
| `onChange` | `(isSelected: boolean) => void` | No | — | Called when selection state changes |
| `isDisabled` | `boolean` | No | `false` | Disable user interaction |
| `isReadOnly` | `boolean` | No | `false` | Read-only mode, no interaction possible |
| `variant` | `"default" \| "accent" \| "secondary"` | No | `"default"` | Visual style variant |
| `isEmphasized` | `boolean` | No | `false` | Apply emphasis styling |
| `children` | `ReactNode` | Yes | — | Switch label text or content |

**Additional Notes**:
- All props follow React Spectrum naming conventions
- Props are case-sensitive
- Default values are shown exactly as they appear in code
- Extends all props from React Spectrum's `@react-spectrum/switch` component

## Variants & States

### Visual Variants

| Variant | Props | Use Case |
|---------|-------|----------|
| Default | `variant="default"` | Standard switches, neutral styling |
| Accent | `variant="accent"` | Important toggles, emphasized switches |
| Secondary | `variant="secondary"` | Less important toggles, secondary choices |

### Behavioral States

- **Enabled**: Normal interaction possible
- **Selected** (`isSelected={true}`): Switch is on/active
- **Unselected** (`isSelected={false}`): Switch is off/inactive
- **Disabled** (`isDisabled={true}`): No interaction, grayed out
- **Read-only** (`isReadOnly={true}`): Shows state but no interaction possible
- **Emphasized** (`isEmphasized={true}`): Emphasized visual styling

Simplest way to use the Switch component.


### Uncontrolled Switch

Switch managing its own state with default initial value.

```tsx
import { Switch } from '@/components/ui/Switch';

export function UncontrolledExample() {
  return (
    <Switch defaultSelected={false}>
      Subscribe to newsletters
    </Switch>
  );
}
```

### Controlled Switch

Switch with state managed by parent component.

```tsx
import { Switch } from '@/components/ui/Switch';
import { useState } from 'react';

export function ControlledExample() {
  const [isSelected, setIsSelected] = useState(false);

  return (
    <Switch
      isSelected={isSelected}
      onChange={setIsSelected}
    >
      Dark mode
    </Switch>
  );
}
```

## Best Practices

- Use clear, concise labels that describe what the switch controls
- Place switches near the setting they control
- Provide feedback when a switch changes state (e.g., visual change, confirmation message)
- Avoid using switches for actions that require additional confirmation
- Consider context: use switches for immediate settings, not major decisions

## Common Issues

**Issue**: Switch doesn't update when clicking the label
**Solution**: Ensure the label is included as children, not in a separate label element. React Spectrum handles label association internally.

**Issue**: Can't find onChange handler
**Solution**: Use `onChange` prop (not `onPress` or `onCheck`). It receives a boolean parameter: `onChange={(isSelected) => ...}`

**Issue**: Disabled switch is still interactive
**Solution**: Make sure `isDisabled` prop is set to `true` (boolean), not `"true"` (string).
